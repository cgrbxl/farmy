# Governance

Initial model: maintainer-led, transparent architecture discussion. The repository owner acts as initial maintainer. No foundation, steering committee or other organisation is implied.

Material architecture decisions use ADRs, recording alternatives and consequences. Contributors can challenge contracts through issues and pull requests. Acceptance should depend on interoperability, user control, security and operational feasibility, not preferred implementation vendor.

Catalogue inclusion must eventually distinguish self-declared compatibility from tested conformance. Listing does not certify agronomic advice or make Farmy responsible for a provider's service.

Maintainer succession, review requirements, release authority and dispute resolution remain to be agreed as contributors join. Licensing is resolved in [ADR 0003](docs/decisions/0003-apache-2.0.md): Apache 2.0, with voluntary sharing of improvements.
