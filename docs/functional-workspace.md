# Functional workspace foundation

The persistent Mac client provides four views over the existing Wallet and Directory Connector. These are client navigation boundaries, not four new backend services.

- **Drive:** browse source files, preview bounded text, admit exact managed copies and exercise real access checks.
- **Copilot:** explicit workspace inventory and grant-receipt questions. Each answer refreshes owner state and labels its basis and timestamp. No model or document contents are used.
- **Hub:** description of the currently fixed local composition. It does not claim continuous health or module installation.
- **Control:** current runtime version, authority rules, persistence and deployment limits. Configuration editing is not implemented in the browser.

Owner views use the existing authenticated state boundary. Consumer sessions retain their restricted read journey and never receive the functional owner navigation. Failed refresh hides owner panels rather than presenting old records as current. Source names are rendered as text, not executable markup. Refresh invalidates previous workspace answers.

## Remaining integration

A document question must use explicit authority for a named processing/model destination and a selected exact version. Private owner-readable items currently do not authorise an independent processor to read them. Resolve that contract and test denial, expiry, revocation, retry and evidence matching before presenting a model-backed answer in this client. Do not promote this interface foundation to completed L3 acceptance.
