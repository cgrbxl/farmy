THE IDEA

Keep authority.
Choose the services.

Information may live in folders, provider stores or independently owned source systems. Each participant retains its own authority; common governance defines how they cooperate.

Farmers choose services and control their own disclosures. AI can help modules adapt to new sources; signed claims can carry evidence of ownership and contributions between participants. Those broader capabilities remain to be implemented.

What the project stands for

  • Control stays explicit. Trusting a service does not grant it access to data.
  • Evidence keeps its origin. Originals, extracted claims and advice stay distinguishable.
  • Modules meet at contracts. Each implementation owns its state and responsibilities.
  • Openness has practical proof. Contracts and tests are independently usable deliverables within the wider product.

COMMON FOUNDATION

Identity & trust · Authenticated communication · Explicit grants · Per-service audit

Conceptual grouping, not a deployment inventory or an all-to-all permission map.

01

Own your state

No service reads another service’s private database. Shared helper code is optional.

02

Bind, then authorise

A binding selects an instance. A grant permits an action. Neither substitutes for the other.

03

Replace with evidence

UC-008 replaces a Knowledge domain provider and rebuilds through public APIs. Independent transport remains unproven.

Where do external wallets, identity and model runtimes fit?

Identity/trust infrastructure and model runtimes can be external dependencies. An attached credential wallet may store, sign, present or verify selected data; it does not automatically replace FarmWallet’s resource and policy authority. The client UI is also replaceable and owns no background execution.

06 / WORKING METHOD

Build vertically. Learn continuously.

Read the working method ↗

A slice is done when…

It runs against real components on the declared target, its acceptance and regression checks pass, and another contributor can reproduce it. We record the limitations and compare actual module changes with the boundaries we expected.
